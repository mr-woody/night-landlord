## 一、项目命名

### 1.1 命名策略

对标微信小游戏爆款命名规律（寻道大千、无尽冬日、咸鱼之王、弹壳特攻队），采用**「3–5 字短主名 + 买量长副标」双层结构**：

- 短主名：注册/商店用，承担品类识别 + 爽点识别；
- 长副标：不注册，只用于买量素材、ASO 副标题、分享卡片，承担爽点直给。

### 1.2 候选池与撞车检索结论

| 候选名 | 品类识别 | 爽点识别 | 独特性检索结果 | 判定 |
|---|---|---|---|---|
| **永夜收租人** | ✅ 永夜=暗黑生存 | ✅ 收租=收益幻想 | **无同名游戏/小说**；题材近邻存在但名称不撞 | **主案** |
| 末日包租公 | ✅ | ✅✅ | ⚠️ **撞车严重**：两部同名小说（[小说阅读网](https://www.readnovel.com/baike/1y2jhj80zbo3d) / [起点](https://www.qidian.com/book/1019409437/)）+ 热播漫剧《我在末日当房东，租客全是S级丧尸》同套路 | 降为备选 |

## 二、平台形态分析：网页 H5 vs 微信/抖音小游戏 vs 原生 App

### 2.1 三条路线对比

| 维度 | 纯网页 H5 | 微信/抖音小游戏 | 原生 App（手游） |
|---|---|---|---|
| 目标受众触达 | 需自带流量，无生态入口 | ✅ 短剧投放主战场（微信/抖音信息流），一键起玩，转化链路最短 | 需跳转应用商店，转化漏斗长、买量成本最高 |
| 买量生态 | ❌ 广告平台基本不支持 H5 落地为小游戏类目 | ✅ 微信广告 + 巨量引擎原生支持小游戏直投 | ✅ 但 CPA 显著高于小游戏 |
| 内购（IAP） | 无官方支付通道，灰色 | ✅ **已打通**（见 2.2 关键政策） | ✅ 标准 App Store/安卓渠道，但苹果抽 30% |
| 广告（IAA） | 自接联盟，eCPM 低 | ✅ 平台广告组件，eCPM 高、接入成本低 | ✅ 接入成本中等 |
| 包体/性能限制 | 无包体限制，性能取决于浏览器 | 主包约 4MB、整包约 20–30MB（以平台最新规则为准），其余走 CDN；2D 完全够用 | 无限制 |
| 审核与合规 | 无审核 | 平台审核快（天级） | 商店审核 + 版号问题（国内 App IAP 需合规资质，小游戏同等要求但生态内成熟） |
| 留存/分享裂变 | 弱（无会话入口） | ✅ 会话分享、公众号、社区入口，裂变链路完整 | 中等 |
| 长线 SLG 演进（Phase 2） | 不适合 | ✅ 无尽冬日类重度产品已验证小游戏可承载 | ✅ 天花板最高 |

### 2.2 关键政策事实（2025–2026，直接影响结论）

1. **iOS 小游戏虚拟支付已合规打通**：2025 年 11 月苹果与腾讯达成协议，微信小游戏/小程序接入 iOS 虚拟支付，苹果按 **15%** 抽佣（低于常规 App Store 30%）；[微信官方 2026 年激励政策](https://developers.weixin.qq.com/minigame/introduction/commercialization/guide/virtual-payment.html)下，符合 MAPP 计划的流水开发者可得 70%+，叠加平台限时补贴实际比例更高（[社区通知](https://developers.weixin.qq.com/community/minigame/doc/000e006da28788b6efc4fd5256b408?source=indexnew)、[21财经](https://www.21jingji.com/article/20251114/herald/e7a9317efd72df99d27a5ead2c65713b.html)）。
2. **2026 年 4 月 1 日起全端强制**：iOS/安卓/鸿蒙虚拟交易必须走官方虚拟支付通道（[解读](https://juejin.cn/post/7635259516817571891)）。
3. **引擎格局**：微信小游戏畅销榜 Cocos 约 41%、Unity 约 32%、Laya 下滑（[Cocos 论坛行业分析](https://forum.cocos.org/t/topic/166479)）；Unity 系通过[团结引擎](https://docs.unity.cn/cn/tuanjiemanual/Manual/weixinminigame.html)支持小游戏（已承载 7800+ 款）；基准测试显示 Cocos 在 2D 渲染性能与 DrawCall 效率上占优（[对比分析](https://my.oschina.net/u/7999656/blog/19692770)）。

> **结论 1：平台策略 = 微信+抖音小游戏优先，H5 只做配套，App 是 Phase 2。**
> - 小游戏是本品类受众（短剧观众、下沉泛用户）的唯一"原生"阵地：买量直投、秒开、会话裂变、IAA+IAP 双通道；
> - iOS 支付政策的落地（15% 抽佣 + 平台补贴）消除了"小游戏不能内购"这个历史上最大的顾虑，小游戏的天平进一步压过 App-first；
> - 纯网页 H5 **不是主阵地**，但仍是必备配套：买量落地页、playable ad 素材、官网——由同一套代码一键导出，零额外成本；
> - 原生 App 在 M3 数据验证后启动（同一代码库出包），承接重度 SLG 化的 Phase 2。

### 2.3 平台决策树

```
是否已有成熟 Unity 团队 + 未来 12 个月内必须上 App 重度 SLG？
├─ 是 → Unity/团结引擎路线（见 3.3 备选）
└─ 否（小团队/新项目/2D 竖屏/小游戏优先）
   → Cocos Creator + TypeScript 全栈路线（主推）
```

## 三、语言与技术栈推荐

### 3.1 主推方案：TypeScript 全栈 + Cocos Creator

| 层 | 选型 | 理由 |
|---|---|---|
| 游戏客户端 | **Cocos Creator 3.x + TypeScript** | ① 微信小游戏畅销榜第一引擎（约 41%），本品类标杆产品（寻道大千/咸鱼之王系）多用 Cocos/Laya；② 2D 竖屏剖面是 Cocos 最强场景，性能优于 Unity 转制；③ **一套工程导出微信小游戏 + 抖音小游戏 + H5 + Android/iOS App**，完全覆盖我们的平台演进路线；④ 引擎免费、国内文档/社区/外包人才最充足 |
| 服务端（MVP） | **Node.js + TypeScript**（微信云开发/云函数起步） | 单机向玩法 MVP 不需要重型服务端：排行榜、支付校验、防作弊校验、远端配置/开关，云函数足够；零运维 |
| 服务端（Phase 2 SLG） | Node.js（NestJS）或 Go + MySQL + Redis，物理服/跨服架构 | 联盟协防、资源市场需要真服务端时再上，M3 验证后决策 |
| 共享层 | **客户端/服务端共享 TS 包**：数值配置、战斗判定逻辑、协议定义 | 全栈同语言的核心价值：① 收租/战斗公式只写一份，防作弊用同一段代码在服务端复算；② 数值策划改 Excel→JSON 双端热更 |
| 数据/运营 | 埋点：ThinkingData/微信数据分析；A/B：平台实验或自建 | 留存/广告位频控/付费卡点全靠数据驱动 |
| 美术管线 | AI 辅助生成 + 骨骼动画（Spine） | 本作对标 AI 漫剧审美，AI 管线与买量素材风格天然一致，且成本优势极大 |

### 3.2 为什么是 TypeScript（而非 C#/Lua/Java）

1. **单语言全栈**：客户端（Cocos 原生 TS）、服务端（Node）、工具链（Excel 导表脚本、买量落地页、可玩广告）全部 TS，小团队心智负担最低。
2. **AI 辅助开发适配度最高**：TS 是主流 AI 编码工具支持最成熟的语言，数值公式、事件系统、UI 框架的迭代速度优势会被持续放大。
3. **数值配置闭环**：策划 Excel → TS 共享模块 → 双端一致，避免"客户端一套公式、服务端一套公式"的经典事故。
4. 人才市场：国内小游戏开发者的主流技能栈就是 Cocos+TS，招聘/外包最容易。

### 3.3 备选方案与切换条件

| 备选 | 适用条件 | 放弃原因（默认情形） |
|---|---|---|
| Unity / 团结引擎（C#） | 团队已有成熟 Unity 经验；或立项即定 App-first + 3D 化 | 本作为 2D 竖屏、小游戏优先；Unity 小游戏链路需转制优化，包体与启动速度劣于 Cocos |
| LayaAir（TS） | 仅当需要极致包体压缩 | 生态与引擎迭代势头不及 Cocos |
| 原生 H5 框架（Phaser/PixiJS） | 只做 playable ad 小样 | 无编辑器、无跨端出包能力，不适合做正式产品 |
| Egret | — | 引擎已停止积极维护，排除 |

### 3.4 技术栈全景图

```
┌─ 客户端 ─────────────────────────────┐
│ Cocos Creator 3.x (TypeScript)      │
│ → 微信小游戏 / 抖音小游戏 / H5 / App │
│ 场景：竖屏剖面楼栋 · 战斗层 · UI层    │
└──────────────┬──────────────────────┘
               │ 共享 TS 包（数值公式/协议/战斗判定）
┌──────────────┴──────────────────────┐
│ 服务端                               │
│ MVP：微信云开发（云函数 Node.js/TS） │
│  · 排行榜 · 支付/广告校验 · 远端配置  │
│ Phase2：NestJS/Go + MySQL + Redis   │
│  · 联盟协防 · 资源市场 · 跨服赛季    │
└─────────────────────────────────────┘
│ 数值管线：Excel → JSON → 双端共享    │
│ 数据：TA埋点 + 平台分析 + A/B        │
│ 美术：AI生成管线 + Spine 骨骼动画    │
```

## 四、结论速览

1. **项目名**：中文主名《永夜收租人》（已检索无同名），出海 Night Landlord，内部代号 Project RN；买量长标"保住邻居，就能无限收租"。
2. **平台**：微信+抖音小游戏优先；H5 仅作落地页/playable ad 配套；原生 App 留到数据验证后的 Phase 2。决定性依据：小游戏是短剧受众的原生阵地 + 2025 年末 iOS 虚拟支付打通且费率（15%）优于 App Store 标准（30%）。
3. **语言**：**TypeScript 全栈**——客户端 Cocos Creator 3.x，服务端先微信云开发后自建 Node/Go；数值与战斗判定做成双端共享 TS 包。备选团结引擎仅在"成熟 Unity 团队 + App-first + 3D"三个条件同时成立时切换。
