# night-landlord 架构需求文档：插件化框架层与全局诊断体系（v1.0）

> 目的：为"插件化内核 + 全局控制 + 日志诊断审计"基础框架层定义**可验收的需求**，作为《插件化内核与诊断体系设计（技术文档 v1.0）》的输入与验收依据。
> 范围：基础框架层（内核/生命周期/热插拔/全局控制/日志诊断）与各业务模块的接入要求。玩法需求见设计方案，数值契约见 M0 文档，模块六问设计见《技术架构与模块规划 v1.0》（下称 v1.0 终稿）。
> 状态：docs-only 阶段，本文档只定义需求与验收，不含实现。

---

## 1. 背景与目标

- 项目现状：纯文档阶段（M0），技术路线已定 Cocos Creator + TS 全栈、共享逻辑包、headless 模拟器为 M1 硬性交付（v1.0 终稿 §5.7）。
- 本轮新增的架构诉求：**便于维护、全局可控、分层明确、功能闭环、依赖关系完整成图、功能热插拔、模块解耦、全局日志诊断（既贯穿全局、又支持分模块诊断与审核）**。
- 参照系：dsh（deepseek-ai/deepseek-harness，"Everything is a Plugin"）基于 Cordis 容器的基础框架层模式——Context 作用域树、服务注入、类型化事件、生命周期 dispose、bundle 组合、headless 去宿主运行。采纳其**模式**、不引入其**运行时包**（理由与边界见技术档 §1、ADR-11）。

## 2. 干系人与核心场景

| 干系人 | 核心场景 |
|---|---|
| 开发者 | 新功能以插件接入而不改旧代码；本地单模块调试、单独启停；看依赖图理解边界 |
| 运维/发行 | 线上紧急关闭某功能（广告、活动、某系统）；远程下发参数修正数值 |
| 客服/支持 | 对玩家问题一键导出诊断包，定位到插件、trace、状态变更 |
| 测试/数值 | headless 快进回归 + 审计报告核对 M0 数值契约与效果操作 |
| 未来协作方 | 依靠机器可读依赖图 + 插件清单接手模块，不读全部代码 |

## 3. 术语表

| 术语 | 定义 |
|---|---|
| 插件 Plugin | 功能的最小生命周期单元：声明依赖服务、提供服务、消费/产出事件、配置 schema、生命周期钩子 |
| 内核 Kernel | 插件容器：负责解析、启动、卸载、事件路由、作用域管理；不含任何游戏知识 |
| 作用域 Scope | 内核 Context 子树，一组可整体挂载/卸载的插件（赛季包、A/B 变体、调试工具） |
| Bundle | 预设的插件组合，定义宿主差异（client / headless / cloud / dev） |
| 热插拔分级 | 插件注册时声明：`core`（不可卸）/ `standard`（启动期可选）/ `removable`（运行时可停）/ `scope`（作用域挂载） |
| Kill switch | 运行时优雅停用某 removable 插件的控制指令，要求降级后主循环不受损 |
| Trace / Span | 一次跨插件业务流（天结算/夜战/事件链/存档）的追踪标识与分段 |
| Health / SelfTest | 插件自报健康三态 / 插件范围内不变量自检套件 |
| 审计 Audit | 对状态变更与控制面操作的可追溯记录（来源、操作摘要、前后哈希、traceId） |
| 功能闭环 | 每个功能必须闭合的七槽位链路（见 FR-F1） |

## 4. 功能需求（FR）

### FR-A 插件化与生命周期

- **FR-A1** 一切功能皆为插件：必须声明 `depends`（服务依赖）、`provides`（提供服务）、事件消费/产出、配置 schema、生命周期钩子（setup/start/stop/drain/dispose）。未声明依赖的服务引用视为构建错误。
- **FR-A2** 依赖解析：按拓扑序启动、逆序卸载；缺失依赖启动期 fail-fast；循环依赖启动期报错并给出环路路径。
- **FR-A3** 故障隔离：单插件 setup/start 失败只停用该插件及其依赖子树，内核与核心日循环（白天经营→夜战→收租）必须继续；故障插件标记 degraded 并进诊断流。
- **FR-A4** 生命周期契约：stop 前必须 `drain()`（状态经 EffectOp 落盘、取消进行中的异步）；dispose 后不得残留监听/定时器/订阅（泄漏可检测）。

### FR-B 热插拔

- **FR-B1** 四级热插拔分级强制声明：`core / standard / removable / scope`（典型归属见技术档 §3）。
- **FR-B2** 启动期组合可裁剪：按 Bundle + 本地配置决定 standard 插件是否安装（如 headless 不装 ads/iap）。
- **FR-B3** removable 插件运行时可 stop/start：stop 前状态经 EffectOp 落盘；**stop 后当日循环、收租结算、存档必须不受损**（降级路径在插件文档中明示，如 ads 停用=无 ×2 奖励入口而非崩溃）。
- **FR-B4** scope 作用域插件（赛季内容包、A/B 变体、调试工具）可整体挂载/卸载；卸载判定 = 监听/定时器/订阅计数归零。
- **FR-B5** 无隐藏状态：任何可卸载插件重挂后必须能仅从 GameState + 配置重建，禁止插件私有持久状态逃逸到存档 schema 之外。
- **FR-B6** 平台约束如实落地：热插拔 = **预置插件的运行时启停 + 数据级热更**（config/event_lib/monster 等 JSON 走远程配置），**不含远程代码下载**（微信小游戏禁止动态代码加载）。

### FR-C 全局控制

- **FR-C1** 统一 ControlService：feature flags（编译默认 + 远程覆盖）、kill switch、远程配置（版本化、可回滚）、模拟控制（timeScale/pause/step，仅 debug 构建生效）。
- **FR-C2** kill switch 保障：任何 removable 插件被停用后，主循环/存档/结算照常；停用动作本身可审计。
- **FR-C3** 配置变更单一通道：全部经 ControlService 应用并广播 `onConfigChange`；禁止插件各自拉取远程配置。
- **FR-C4** 控制面全留痕：flags/kill switch/配置变更记录操作者、时间、变更前后值。

### FR-D 解耦与依赖

- **FR-D1** 服务只经注入获取；插件间禁止直接 import 对方内部模块（CI 静态检查）。
- **FR-D2** 跨插件通知走类型化事件；事件词汇表集中定义，分三类：Domain（业务事实）/ Control（控制面）/ Diag（诊断流）。词汇表外的 tag 视为错误。
- **FR-D3** 依赖图机器可读：可导出 JSON（节点=插件，边=服务依赖与事件流）；CI 校验无环、分层禁引用、未声明依赖。
- **FR-D4** 维持 v1.0 决策 D4：决策与执行分离（Director/事件产出 EffectOp，`applyEffects` 单点执行）；任何框架机制不得提供绕过它的状态修改通道。

### FR-E 全局日志与诊断（贯穿 + 分模块）

- **FR-E1** 结构化日志：`{logicalDay, wallTs, level, channel(=插件名), traceId, spanId, msg, data}`；逻辑层日志由内核信封注入时间与 trace（延续 v1.0 确定性禁用清单：逻辑层不取墙钟、不取随机）。
- **FR-E2** Trace 贯穿：天结算、夜战会话、事件链、存档四类关键流有标准 span；traceId 随事件信封与 EffectOp 自动透传，无需各插件手工传递。
- **FR-E3** 日志基础设施常开：内存环形缓冲（上限 512 条）保底可导出；开发控制台可按通道过滤、运行时调级；高频日志（战斗帧）采样。
- **FR-E4** 分模块诊断：每插件实现 `health()`（ok/degraded/fail + 详情）与可选 `selfTest()`（插件范围内不变量自检，如经济对账、人口上限、事件频控预算）。
- **FR-E5** 审计：状态变更审计（`applyEffects` 挂钩自动记录来源插件/操作摘要/前后状态哈希/traceId）+ 控制面操作审计 + 配置变更审计；环形存储、可导出；M3 起随异常上报。
- **FR-E6** 一键诊断包：日志环 + 指标快照 + 全插件健康 + 近期审计 + 配置快照（脱敏）+ 存档版本，体积 ≤200KB，客服可要求玩家导出。
- **FR-E7** headless 同权：无宿主环境下提供同名 `diagnose` 命令与相同报告结构。

### FR-F 功能闭环

- **FR-F1** 每个插件交付必须填写"闭环七槽位"清单：①输入命令 ②校验规则 ③执行与审计挂钩 ④产出事件 ⑤存档覆盖（哪些状态进检查点）⑥遥测埋点 ⑦降级与可停路径（含 kill switch 后行为）。
- **FR-F2** 缺任一槽位，不得通过该里程碑的插件验收（模板化检查项，评审时逐项过）。

### FR-G 宿主与平台适配

- **FR-G1** 同一内核 + 同一套逻辑插件跑三宿主：Cocos（真机/小游戏）、headless（模拟器/复算/CI）、云函数；宿主差异**只**体现为 Bundle 组合与平台适配插件。
- **FR-G2** 平台能力（广告/支付/云存储）全部为 removable 插件且 fail-open：平台不可用时游戏可完整游玩（无广告奖励、单机存档）。

### FR-H 可维护性

- **FR-H1** 插件接入有文档化模板：新插件按模板复制七槽位 + 分级声明 + 依赖声明，评审对照验收。
- **FR-H2** 内核 API 治理：M1 结束冻结 minor 版本；破坏性变更走 ADR 并提供迁移说明。
- **FR-H3** 每个插件 README 必含：分级、依赖图位置、七槽位清单、selfTest 说明。

## 5. 非功能需求（NFR）

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 内核运行开销 | 常规帧 <0.5ms；启动到可玩增量 <100ms |
| NFR-2 | 日志量预算 | 常规 ≤2,000 条/日会话；环形缓冲 ≤512 条；诊断包 ≤200KB |
| NFR-3 | 包体 | 内核 + diag ≤30KB（min+gzip）；逻辑包总预算 <100KB（v1.0 NFR 延续） |
| NFR-4 | 确定性不被破坏 | 诊断/控制面在逻辑层零副作用；同 seed 双跑哈希全等（CI） |
| NFR-5 | 可靠性 | 单插件故障不产生坏档；内核级故障走进程重启 + 检查点恢复 |
| NFR-6 | 平台兼容 | 微信/抖音/H5/Node 全兼容；内核无 Node 专有 API |
| NFR-7 | 主包 | 微信主包 ≤4MB（v1.0 NFR 延续，逻辑包 <100KB） |

## 6. 约束

- **C1** M0 数值契约冻结：D1 租金 1000±5%、r(7)=1.02±0.05 等锚点不可被任何框架机制破坏；一切状态变更必须过 `applyEffects`。
- **C2** 技术栈冻结：TS 全栈、npm workspaces、微信小游戏首发；不依赖 `cordisjs/cordis` 或 `@deepseek-ai/*` 运行时包（ADR-11）。
- **C3** 阶段约束：本文档与配套技术档只做设计与验收定义，不落代码（docs-only）。

## 9. v2.0 增补：世界空间系统功能需求（FR-W，M3.0 2026-08-30）

> 来源：《世界观与空间结构设计 v1.0》三层空间模型（L1 野外/L2 小区/L3 室内）。
> 全部新增系统以插件接入（FR-A 全适用），状态变更一律 EffectOp（D4），确定性 RNG 日域流（禁 Math.random/Date.now）。

### FR-W1 worldmap 插件（空间状态）
- 维护三层空间状态：楼栋（栋/层/房）、小区地块（大门/围墙/公共建筑落位）、野外地块（区域/采集点/野物出没）。
- 房间全局标识 `lotId:buildingId:floor:room`；既有 `F{n}-R{n}` 模型映射为默认栋 A 的等价表达（M0 数值窗口内夜战目标不换名）。
- 提供视口/落位查询服务（渲染层只读消费）；空间状态进日检查点。

### FR-W2 explore 插件（外出探索）
- 白天可派 1–3 名住户外出：目的地、体力消耗、时间消耗（可跨入夜点→夜晚滞留）。
- 产出（采集/狩猎）经 EffectOp 入六资源体系；危险野物战斗自动结算+技能干预（FR-W4）。
- 数值键走 constants `EXPLORE_*` 命名段；产出平衡独立副表，不触碰 day_curve 主曲线（M0 契约 C1）。
- kill switch 停用后：主循环/收租/存档不受损（仅失去野外玩法入口）。

### FR-W3 interior 插件（房屋内部）
- 房间内部状态：工事位（门/窗/家具）占用、住户岗位与状态机投影；数据与既有 fort 槽位/岗位模型同源，不另立状态。
- 室内专属事件组 `evt_in_*` 经既有事件管线（selectDay 同规则）触发。

### FR-W4 wildlife 插件（野物生态）
- 野物出没表（按区域/昼夜/天数段）；猎物产出与危险野物战斗（自动结算，玩家可技能干预）；战败后果=住户受伤/物资损失（禁 KILL_TENANT 于野外，护"苟神不死"原则）。
- 遭遇判定用 `createDayRng(seed,'wildlife',day)` 独立流，同 seed 双跑可复现。

### FR-W5 渲染非功能需求（客户端）
- 类 3D（斜 45° 等距）三层视图；同屏绘制调用预算 ≤60（微信小游戏白盒期实测）；
- 镜头：L1/L2 缩放+平移（边界钳制）、点击建筑推镜进 L3；全天昼夜光照映射（白天暖金/黄昏橙红/夜晚深蓝、血月红）。
- 白盒期以程序化组合体表达；该要求为表现层验收，不进内核 NFR 表。
