## 一、审核结论：v0.1 → v1.0 的八处修订

| # | 审核发现（六问触发） | v1.0 修订 |
|---|---|---|
| 1 | Formula 若在运行时算 `1.12^d` 类公式，`Math.pow` 属 ES 实现相关超函数，跨端（iOS/安卓/云函数 Node）浮点结果可能不一致，破坏服务端复算 | **曲线表驱动**：M0 主表 31 行直接入库为 `day_curve.json`，运行时只查表+乘数组合+整数取整，禁用超越函数。M0 表从"调参产物"升级为**运行时数据源** |
| 2 | A08 遭遇表（敲门人/救援任务）与事件系统是同一引擎的两种内容形态，分开建会出两套触发/后果/频控代码 | **遭遇并入 `event_lib`**，以 `choice`（抉择型）与 `mission`（任务型）两种 type 区分，一套 Director 引擎承载 |
| 3 | M0 的聚合比值 r=F/T 与实际"多路分散防守"的路级战斗没有桥接，M1 实现时会对不上 | 明确校准关系：**r(d) 是"均匀分配防御下的期望值"**，实际战斗在路级判定 `r_i = F_i / hp_i` 后聚合；路级死亡带与 M0 死亡带同表；模拟器以"均匀分配"模式回放校验 M0 锚点 |
| 4 | Director 若直接改写 GameState，无法单测且无法实施全局护栏 | **效果命令模式**：Director/事件只产出 `EffectOp` 命令列表，由 systems 层唯一的 `applyEffects()` 执行并校验护栏（单日死亡 ≤4 等） |
| 5 | 恐慌/公约在 M0 中只有定性描述，实现时无数据可依 | **恐慌数值化**（首版示意，进 `constants.json`，M1 模拟器回归验证不破坏锚点）：见 5.3 |
| 6 | 异常检测缺"正常带"定义 | **复用 M0 曲线带**：`day_curve.json` 即正常带数据源，偏离即异常（见 5.6） |
| 7 | 服务端复算若理解为"全量权威"，MVP 做不完 | 诚实定位：**MVP=客户端权威 + 云函数抽样复算**（战斗会话重放比对结算哈希），全量权威留 Phase 2（ADR-5） |
| 8 | Stabilizer 若 M2 直接生效，可能与"复利爽感"冲突且无法归因 | **三级递进**：M2 只记录 → M3 软调制（限幅 ±10%）→ M4 远程参数生效；任何调制不得破坏 M0 契约锚点 |

## 二、全局架构决策

**七条原则**：① 表驱动（曲线/事件/怪物全配置化，公式零魔法数字）；② 确定性优先（逻辑层禁墙钟、禁 Math.random、禁超越函数）；③ 命令式效果（决策与执行分离，护栏单点化）；④ 单一状态树（GameState 唯一，序列化即存档）；⑤ 逻辑包零平台依赖（Cocos/Node/云函数共用同一份）；⑥ 治理三级递进（记录→软调→生效）；⑦ 每模块只做最小可用版（防底座体量错配）。

| ADR | 决策 | 状态 |
|---|---|---|
| D1 | 强度公式弃 `(1+0.18d)^1.35`，改 `HP0×1.15^(d-1)×J`（来源 M0 §9.1） | 已定 |
| D2 | 血月跳变日 = 7/14/21/28，D30=满层+夜王预告（M0 §9.2） | 已定 |
| D3 | 运行时曲线查表化，`day_curve.json` 为唯一数据源 | 已定（本版修订 #1） |
| D4 | 效果命令模式：Director/事件产出 `EffectOp`，systems 单点执行 | 已定（修订 #4） |
| D5 | MVP 反作弊 = 客户端权威 + 抽样复算 | 已定（修订 #7） |
| D6 | M0 事件文案库按 `event_lib` schema 结构化编写 | 已定 |
| D7 | Stabilizer 三级递进（记录/软调/生效） | 已定（修订 #8） |
| D8 | 住户不做个体 Agent AI：怪物三段式 + 事件 NPC 两维可信度 | 已定 |
| D9 | Monorepo 用 npm workspaces；Cocos 集成方式 = **(a) 源码同步脚本**（`scripts/sync-cocos.mjs`：拷贝 `packages/*/src` 至 `apps/client-cocos/assets/scripts/shared/`，改写 `@rn/*` 跨包导入为相对路径，生成校验和清单防漂移）。微信编辑器构建为人工验证步骤（M1 验收门③），结果记入 M1 证据台账 | 已决策（2026-08-30，代码侧完成） |
| D10 | 测试三类（单测/headless 契约/冒烟），不设行数 KPI | 已定 |

## 三、总体架构

### 3.1 分层与依赖（箭头只允许向左/向下）

```
┌─────────────────────────── 应用层 ───────────────────────────┐
│  apps/client-cocos        apps/headless        云函数(MVP服务端) │
│  表现/输入/UI/音频         模拟器·复算·契约测试    抽样复算·排行榜  │
└──────┬───────────────────────┬──────────────────────┬────────┘
       │ 绑定引擎帧/渲染          │ 快进 runner           │ 复算同一份逻辑
┌──────┴───────────────────────┴──────────────────────┴────────┐
│  systems   经济/住户/防御/怪物/存档/效果执行(护栏单点)              │
├──────────────────────────────────────────────────────────────┤
│  director(事件/夜计划)   stabilizer(只读度量→限幅修正)            │
├──────────────────────────────────────────────────────────────┤
│  formula(查表+乘数,纯函数)         core(tick/RNG流/事件总线/命令)  │
├──────────────────────────────────────────────────────────────┤
│  config/*.json  day_curve·constants·monster·iap_sku·event_lib·building_def │
└──────────────────────────────────────────────────────────────┘
  observability：逻辑层只发 DomainEvent，sink 由应用层注入（逻辑包零上报依赖）
```

依赖规则：director 与 stabilizer **不 import systems**（director 出命令、stabilizer 出修正量），保证可单测与护栏单点。

### 3.2 Monorepo 布局（npm workspaces）

```

│   ├── core/            @rn/core        tick、RNG流、事件总线、命令通道、错误边界
│   ├── formula/         @rn/formula     查表+乘数组合的纯函数集
│   ├── systems/         @rn/systems     GameState、经济/住户/防御/怪物、applyEffects、存档
│   ├── director/        @rn/director    事件调度、NightPlan、触发引擎
│   ├── stabilizer/      @rn/stabilizer  度量、限幅修正
│   └── observability/   @rn/observability  DomainEvent 定义与 sink 接口
├── config/              day_curve / constants / monster / iap_sku / event_lib / building_def
├── apps/

│   └── client-cocos/    Cocos 工程（shared 逻辑经 M1 spike 确定的方式接入）

```

### 3.3 平台集成约束

- 微信小游戏主包 ≤4MB：逻辑包纯 TS 预计 <100KB 无压力；美术/音频走远程 CDN 包。竖屏 2D 剖面，DrawCall 合批写进 M2 性能预算。
- 云函数（MVP 服务端）：复算函数打包 `@rn/*` + `config/`，逻辑包体积小、冷启动无风险。
- **M1 spike（ADR-9）——已结案（2026-08-30）**：采方案 (a) 源码同步脚本：`scripts/sync-cocos.mjs` 把 `packages/*/src` 拷入 `assets/scripts/shared/`，改写 `@rn/*` 跨包导入为相对路径，生成校验和清单 `manifest.json`（`--check` 防漂移，进 CI）。"同一份逻辑单测在 Node 侧跑通"已自动化；"微信开发者工具构建通过"为人工五步（见 `apps/client-cocos/README.md`），结果记入 M1 证据台账。

## 四、运行模型：一个游戏日的生命周期

### 4.1 相状态机与当日时序

```
DAWN_SETTLE ──▶ DAY(经营,~2.5min) ──▶ DUSK_FORECAST ──▶ NIGHT(战斗,~1.5min) ──▶ DAWN_SETTLE …
```

| 相 | 逻辑动作（顺序固定，保证确定性） | 存档检查点 |
|---|---|---|
| DAWN_SETTLE | ①存活名单结算 → `formula.dailyRent`（收租×2 广告在此时乘算）②恐慌传播与衰减 ③出逃掷骰 ④Director `ON_DAWN` 事件 ⑤离线收益在此合并 | ✅ |
| DAY | 玩家操作=命令（招募/升级/分配/建造/用道具）逐条校验生效；`ON_EVENT_SLOT` 触发每日 1–2 个 `event_lib` 事件 | 命令即时生效，不入档（下次检查点覆盖） |
| DUSK_FORECAST | `director.planNight(d)` 生成 NightPlan；瞭望塔等级决定预告精度 | — |
| NIGHT | 打开 BattleSession：15Hz 战斗帧推进自动战斗，玩家技能施放记入输入日志；关闭时路级结算→死伤 | ✅（含会话日志） |

Tick 粒度：经济事件驱动 + 1s 心跳；只有 NIGHT 内部用 15Hz 固定战斗帧。**战斗确定性问题的范围被压到会话内部**，省性能也好测试。

### 4.2 核心数据契约

```ts
// NightPlan（DUSK_FORECAST 产出，M0 的 W/hp/J 是它的数据源）
interface NightPlan {
  day: number
  routes: { roomId: RoomId; monsters: MonsterSpawn[] }[]   // 路数 = min(1+⌊d/4⌋,5)+(血月+1)
  modifiers: ('BLOOD_MOON' | 'SILENT' | 'MIGRATE')[]       // 血月日 J=CFG_J_BM=1.6
  seed: number
}

// BattleSession（一夜=一个会话，可序列化=可重放=可复算）
interface BattleSessionLog {
  plan: NightPlan
  defenseSnapshot: PostLayout        // 开战时布防快照
  inputs: { frame: number; skill: SkillId; target?: RoomId }[]  // 玩家干预时间轴
  settlementHash: string             // 结算结果哈希（复算比对用）
}

// 路级判定（规则配置化，对应 F05/Rules；带值=M0 死亡带）
judgeRoute(r_i: number): 'HOLD' | 'HOLD_WOUNDED' | 'LOSE_1' | 'LOSE_2' | 'LOSE_3P'
// r_i≥1.20 守住 ｜ 1.05–1.20 轻伤 ｜ 0.95–1.05 死1 ｜ 0.80–0.95 死2 ｜ <0.80 死3+

// EffectOp（命令式效果，护栏在 applyEffects 单点校验：单日死≤4、30日累计≤6）
type EffectOp =
  | { op:'ADD_GOLD'|'ADD_RES'; res:ResId; n:number }
  | { op:'SPAWN_TENANT'; quality:'N'|'R'|'SR'|'SSR' }      // 走招募池权重（A13）
  | { op:'KILL_TENANT'|'WOUND_TENANT'; tenantId:ID }
  | { op:'ADD_PANIC'; tenantId?:ID; floor?:number; n:number }
  | { op:'SET_FLAG'; key:string; v:number|boolean }         // 事件记忆/口碑（A09/信息系统裁剪版）
  | { op:'NIGHT_MOD'; mod:'BLOOD_MOON'|'SILENT'|'MIGRATE' }
```

### 4.3 M0 聚合 r 与路级战斗的校准（修订 #3 展开）

- M0 主表的 `r(d)=F/T`：定义为**均匀分配防御下的期望比值**，用途是曲线设计与验收。
- 实际夜战：玩家把有限防御点分到 W 路上 → 每路 `r_i = F_i/hp_i`（`ΣF_i ≤ F(d)`），逐路查死亡带后聚合死伤。
- **分散防守谜题 = 分配问题**：护 A 漏 B 在数值上表现为部分路 `r_i<1`；玩家的策略价值全部体现在分配上，聚合值可以持平甚至好于均匀分配。
- 模拟器提供两种布防模式：`uniform`（校验 M0 锚点）与 `greedy`（验证"最优分配"收益上限，供 M2 平衡参考）。

### 4.4 离线结算

离线收益**不逐 tick 模拟**：`离线收益 = f(离线时长, day_curve 查表, 仓容上限)`，回流时并入 DAWN_SETTLE（"离线收益×2"广告在此时乘算）。headless `verify` 模式校验离线公式与逐日模拟的一致性误差 ≤5%。

## 五、模块深度设计（六问逐模块）

> 每模块按【职责｜不做什么｜接口草图｜数据契约｜失败模式与降级｜里程碑与验收】六问收口。

### 5.1 `@rn/core`（Tick 引擎/模块注册表/RNG/事件总线/错误边界）

- **职责**：固定逻辑帧与相状态机；可序列化的分流 RNG；DomainEvent 总线；命令通道；异常边界（单系统抛错不拖垮整日循环，小游戏防白屏）。
- **不做**：任何游戏规则；任何平台 API。
- **接口草图**：

```ts
type StreamId = 'director' | 'monster' | 'tenant' | 'loot'
interface Rng { next(s: StreamId): number }        // mulberry32(seed ⊕ hash(s,day))，状态可序列化
interface Bus { emit(e: DomainEvent): void; on(t: Tag, fn: Fn): Unsub }
interface CmdBus { dispatch(cmd: PlayerCmd): Result }   // 命令→校验→applyEffects
```

- **失败模式**：命令非法 → 返回 Result 并埋点，不改状态；系统抛错 → 隔离到该系统，天亮结算兜底。
- **里程碑**：M1。验收：同 seed 两次完整日循环，DomainEvent 序列全等。

### 5.2 `@rn/formula`（公式注册表：查表 + 乘数组合）

- **职责**：M0 三曲线的唯一实现处。`dailyRent(state,M)`（=Σ户产×q×u×M）、`threat(d,plan)`、`defensePower(state)`、`offlineIncome()`、月卡/天赋/公约乘数合成。曲线一律查 `day_curve.json`（31 行），修正量查 `constants.json`（`CFG_R0=100、CFG_G_U=1.055、CFG_G_T=1.15、CFG_HP0=100、CFG_J_BM=1.6、CFG_K_POWER=2.6`…，与 M0 §2 同名）。
- **不做什么**：Math.pow/随机/Date/浮点累加不定序；金币一律整数（取整规则写死：逐户 round 后求和）。
- **失败模式**：配置缺失 → 启动期 schema 校验直接 fail-fast（禁止运行时静默缺省）。
- **里程碑**：M1。验收：headless 跑 M0 锚点（D1 租金 1000±5%；r(7)=1.02±0.05；周期 β ±5pp）。

### 5.3 `@rn/systems`（GameState / 存档 / 经济 / 住户 / 防御怪物 / 效果执行）

- **职责**：
  - **GameState 单一状态树**：`{version, day, phase, rng, resources(6种), tenants[], building(房间+公共建筑等级), defense(岗位/武器), flags, stats}`。存档=序列化，版本迁移=migrator 链（B08/Persistence，增量+压缩，M1 雏形）。
  - **槽位模型**（A04/行业槽位裁剪）：`Room{tenantSlot×1, fortSlot×2}` + 公共建筑岗位槽，`building_def.json` 定义各建筑等级→槽数。
  - **住户与人口**（A13 招募池 + Population）：招募池按品质权重 roll（权重来源=M0 品质结构系数 q(d)）；死亡=永久移除（断收入线）；引荐=存活 N 户 3 天后产 SPAWN_TENANT 命令。
  - **恐慌数值化**（F02/Env 裁剪 + 修订 #5，首版示意进 `constants.json`）：住户 panic 0–100；来源：所在房被破 +25、挨饿 +10/日、同层破防传播 +5、事件 effects；衰减 −10/日；后果：单户 ≥70 时每日 15% 出逃、全楼均值 >50 时户产 ×0.9（进 M(d)）；公约=降恐慌但户产 −5%~−10%（M(d) 减项）；**D1–D7 教学段恐慌封顶 30**（保障"苟"的安全感）。
  - **防御与怪物**（Entity/Pathfinding 极简版）：怪物移动=网格直线+破门点，不做导航网格；波次表 `monster.json`（变种/机制/路数修正）。
  - **`applyEffects(ops)`**：全游戏唯一状态变更执行器，护栏单点（单日死 ≤4、30 日 ≤6、资源不为负、人口 ≤ 双上限）。
- **失败模式**：状态损坏 → 存档校验失败时回退上一检查点（每日 3 检查点）；不变量校验失败 → 上报 observability 并降级为只读（防坏档扩散）。
- **里程碑**：GameState/存档/经济/住户 M1；防御怪物夜战 M1、BattleSession M2；恐慌数值 M2。

### 5.4 `@rn/director`（事件调度 / NightPlan / 触发引擎，A10+A08+F03 裁剪合并）

- **职责**：钩子分发（`ON_DAWN / ON_EVENT_SLOT / ON_DUSK_FORECAST / ON_NIGHT_END / ON_TENANT_DEATH / ON_PANIC_HIGH / ON_WEALTH_OVERFLOW`）；从 `event_lib` 按权重×频控×前置选事件；`planNight()` 生成 NightPlan（M0 的 W/hp/J 查表 + 特殊夜修饰）；异象/血月预告节奏器。
- **不做什么**：不直接改状态（只出 `EffectOp`，修订 #4）；不做自然天气/灵气类内容。
- **`event_lib` schema**（M0 事件文案库 50 条按此编写；choice=抉择型，mission=救援/遭遇型，A08 并入）：

```json
{
  "id": "evt_knock_001", "ver": 1, "type": "choice", "title": "深夜敲门人",
  "weight": 10, "cooldownDays": 5, "maxPerRun": 3,
  "prereq": { "dayMin": 3, "panicMax": 60, "flags": {} },
  "text": "门外声音很轻……开，还是不开？",
  "options": [
    { "label": "开门", "outcomes": [
      { "p": 0.7, "text": "是一家三口，厨师老张加入了。", "effects": [{"op":"SPAWN_TENANT","quality":"R"}] },
      { "p": 0.3, "text": "它的皮肤在月光下剥落了……", "effects": [{"op":"NIGHT_MOD","mod":"SILENT"}] } ]},
    { "label": "隔门询问", "outcomes": [ { "p": 1.0, "effects": [{"op":"SET_FLAG","key":"reputation","v":1}] } ]},
    { "label": "无视", "outcomes": [ { "p": 1.0, "effects": [{"op":"SET_FLAG","key":"reputation","v":-1}] } ]}
  ]
}
```

- **频控预算**：每日 1–2 槽位 × 30 天 ≈ 45–60 次触发 / 50 条库 → 单条平均出场 ≈1 次，`weight` 拉开叙事节奏（教学事件 weight 高、日常事件低），M0 文案库须给每条默认 `cooldownDays`。
- **事件 NPC 可信度**（B11/11 维决策链裁剪，D8）：`可信度 = 特质匹配 × (1 + flags.reputation×0.1)`，两维而已；"连续性"体现为 flags 记忆（防选择反复横跳的叙事一致性）。
- **失败模式**：无可触发事件 → 保底池（低权重日常事件永不耗尽）；NightPlan 生成失败 → 降级为标准夜（无修饰）。
- **里程碑**：M1 固定脚本版（教学序列写死）；M2 完整版（权重/频控/前置 + 特殊夜三机制 + 救援 mission 型）。

### 5.5 `@rn/stabilizer`（度量 / 限幅修正，A11 裁剪；三级递进 D7）

- **职责**：只读度量（财富指数、7 日产出/消耗比、恐慌总量、死亡累计）→ 产出修正量：`nightJAdjust ∈ [0.9,1.1]`（乘 `CFG_J_BM`）、`rentDamping ≤1`（仅对**爆仓溢出部分**的边际收益衰减）。
- **不做什么**：不改公式结构；不碰未爆仓的正常收益（护住"复利可见"爽感）；M2/M3 不自动生效。
- **三级递进**：L1（M2）只打点；L2（M3）软调制——仅当玩家指标偏离 M0 正常带（如 30 日死亡 >6 或仓库连续 7 日满仓）才启动，限幅 ±10%，每次调制记快照（可归因）；L3（M4+）云函数远程下发 `constants.json` 子集参数（如 `CFG_J_BM`、阻尼阈值），不热更代码。
- **失败模式**：度量缺失 → 不修正（fail-open），绝不因稳定器故障压产出。
- **验收**：任何调制下 M0 锚点带仍成立（模拟器带 stabilizer 回归跑锚点）。

### 5.6 `@rn/observability`（埋点 / 异常检测 / 快照 / 经济账本，A12+A17 裁剪）

- **职责**：DomainEvent 分类上报（日汇总经济、夜战结果、事件抉择、广告观看、IAP、会话、异常）；**异常检测以 `day_curve.json` 为正常带**（修订 #6）：金币日增 > 带宽 ×3×（广告×2 × 月卡 1.15 的合法上限）、人口 > 双上限、进度回退、复算哈希不符 → 打 `anomaly` 事件；存档快照导出（客服取证）；**经济账本**（A17）：MVP 客户端日汇总 → M4 云函数聚合全服产出/消耗总账（礼包定价依据）。
- **接口**：逻辑层只 `emit(DomainEvent)`；`TelemetrySink` 由应用层注入（Cocos 绑 ThinkingData/微信分析，headless 绑 noop）。**逻辑包零上报依赖**。
- **里程碑**：M2 埋点；M3 异常检测上线（外挂与数值异常预警）；M4 服务端账本 + 对账验收（全服产出 = 消耗 + 玩家沉淀，误差 <0.5%）。

### 5.7 `apps/headless`（无头运行器：simulate / verify / replay）

- **职责**：① `simulate --days N --profile f2p|payer|uniform|greedy`：快进跑 D0–D30，输出逐日报告（M0 验收的数据来源）；② `verify --save`：不变量校验 + 锚点契约测试 + 离线公式一致性；③ `replay --session`：按 BattleSessionLog 重放比对 `settlementHash`（服务端复算同款）。
- **为什么它是硬性交付**：M0 §11 的验收标准全部靠它执行；MVP 反作弊（抽样复算）= 云函数里跑同一个 `replay`。
- **里程碑**：M1（必须，先于客户端可玩）；CI 接 GitHub Actions：每次提交自动跑 `simulate --days 30` 契约测试。

## 六、横切机制

### 6.1 确定性与反作弊（D3/D5）

- **禁用清单（逻辑层 CI 静态检查）**：`Math.random`、`Date.now`、`Math.pow/exp/log/sin…`、对象键序遍历（一律数组+下标）。
- RNG 分流（director/monster/tenant/loot 四流，互不耦合顺序），状态可序列化入存档。
- **MVP 反作弊流程**：夜战结束 → 客户端上送 `BattleSessionLog` → 云函数按概率抽样（新用户/高分/异常标记优先）`replay` → 比对结算哈希 → 不符打 anomaly 并冻结奖励。离线收益服务端按上限公式校验；广告/支付走平台服务端回调校验。全量权威复算留 Phase 2（自建服务端时）。

### 6.2 存档与版本迁移

- 每日 3 检查点（天亮结算后 / 入夜前 / 夜结算后）+ 关键命令后脏标记；云开发存档 + 本地兜底；`version` 递增 + migrator 链，迁移失败回退检查点。单设备为主，多端冲突 last-write-wins（记录为已知限制，Phase 2 服务端解决）。

### 6.3 性能与包体预算（NFR，B10/Rendering 落点）

| 项 | 预算 | 验收点 |
|---|---|---|
| 微信主包 | ≤4MB（逻辑包 <100KB） | M1 构建检查 |
| 首屏可交互 | 中端机 <3s | M2 |
| 战斗帧率 | 逻辑 15Hz 固定；渲染低端机 ≥30fps、中端机战斗场景 ≥50fps | M2 |
| 物资雨动画（标志性瞬间） | 中端机 ≥25fps，粒子 LOD 三档 + UI 合批 | M2 专项 |
| 云函数复算 | <3s/次（抽样） | M3 |
| 存档体积 | 压缩后 <200KB | M1 |
