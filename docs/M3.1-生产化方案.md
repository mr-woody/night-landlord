## 2. 方案选择（关键决策点，择优记录）

### 决策 K1：探索并入主循环的方式
| 选项 | 评估 |
|---|---|
| A. 探索作为日循环固定阶段（可选 flag 开关） | ✅ **采纳**：确定性、可检查点、flag 关闭后与 M0 锚点逐字节兼容 |
| B. 完全异步于主循环（玩家手动触发才结算） | 单机可玩但 headless 不可复算，违背 NFR-4 确定性 |
| C. 并入且无条件开启 | 破坏 M0 锚点复算（C1 冻结），verify --design 无法保证逐字节 |

→ **K1=A**：`EXPLORE_ENABLED` flag 门控；verify --design 关闭态复跑 M0 全门（逐字节保 M0 契约），新增 `verify:explore` 开启态跑 V13 产出锚点（EXPLORE_YIELD_TARGET_D8/D30）。

### 决策 K2：野外经济与 M0 契约的关系
- 产出只入 food/water/material（六资源再分配），不入 gold/income 主曲线（保 V9 β_sim/V10 ΣI 不受扰动）；
- 野物战败 WOUND 会抬恐慌→出逃→人口→rent 链路，**锚点窗口（D1–30）内探索遭遇率对 verify --design 路径为 0**（K1 关闭态），开启态走 V13 独立预算；
- 检查点：WorldState 与 GameState 同帧落盘（persistence 双键 `ckpt_<d>_world`）。

### 决策 K3：渲染路线
- Canvas 桥保留至素材期（M3 素材管线就绪前生产 UI 继续用程序化 2.5D；已通过 M2.6 视觉验收）；
- Creator 原生节点替换排 M3 素材期（P6 路线 B），不做双轨维护。

### 决策 K4：商业化插件骨架
- 严格按 FR-B/G2：ads/iap 为 removable + fail-open；接口先行（offerXxx/show/setListener），平台实现 M4 接；
- kill switch 验收进 D3（FR-B3：停用后日循环/收租/存档不受损）。

## 4. 技术方案（关键实现要点）

- **探索策略（确定性）**：`explorePolicy(state, world, tables, day)` → 纯函数输出当日派遣（队伍=体力最高且非岗位住户的前 3 名；目的地=已解锁且 danger 最低的 zone）；policy 属 director 职责域，接进 `runSimulation` 时以 options.explore 开关。
- **落点**：`runSimulation` 白天阶段末尾 `dispatchParty(...)`；`resolveDue` 在 DAWN 段（restoreStamina 前）；WorldState 持久化 `ckpt_<d>_world`；DayRecord 增 `exploreYield` 字段（加法，finalHash 变化可接受——锚点门不依赖 finalHash）。
- **V13**：`verify --explore`：开 flag 跑 30 天，断言 `Σ world.totalYield折算` 落在 EXPLORE_YIELD_TARGET_D8/D30 区间（折算表：食物=1、水=1、建材=2）。
- **插件化**：world 以 `definePlugin` 包装注册（provides 'world'），供 director/persistence 消费——保持 FR-D 服务注入，不全局单例。

## 7. UI 交互稿（生产化补充，交互体验原则）

- **存档提示**：检查点写入时 HUD 角标「已存档 ✓」淡入淡出 800ms（fast 曲线）；掉线恢复走最近检查点面板（§四 fail-safe 延续）。
- **商业化入口**：收租×2 按钮常驻结算面板右下（88px 热区，金色描边+微动效），不带强制弹窗（IAA 合规）；夜间空投支援入夜战面板技能区第三格。
- **设置页扩展**：概率公示入口（跳转导出 JSON 渲染页）、隐私协议、版本号——列表行沿用 settings 组件。
- **体验原则**：任何面板可被事件卡打断排队（既有）；所有新入口热区 ≥88px；文案 24px 起步。
