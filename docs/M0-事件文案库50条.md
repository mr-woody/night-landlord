# M0 · 事件文案库 50 条（event_lib 结构化 schema v0.1）

> 定位：M0 交付物之二（其一为《M0-数值模型-三曲线调参表》）。本库按《插件化内核与诊断体系设计》§5.4 的 `event_lib` schema 编写，是**数据设计**而非代码：M2 Director 引擎直接消费本表导出的 JSON。
> 效果算子沿用 v1.0 终稿 §4.2 的 `EffectOp` 词汇（ADD_GOLD / ADD_RES / SPAWN_TENANT / WOUND_TENANT / ADD_PANIC / SET_FLAG / NIGHT_MOD / GRANT_BUFF），金额为 F2P 基准下的首版示意值。
> 题材基准：末日永夜 + 包租公收租；文案对齐短剧受众（口语、反转、每条正文 ≤60 字）。概率 p 均为首版示意，M2/M3 依触发率报表回调。

## 1. 库级规则与频控预算

| 规则 | 值 | 依据 |
|---|---|---|
| 条目总数 | **50**（教学 8 + 抉择 24 + 任务 10 + 秩序社区 8） | 设计方案 4.8"每日 1–2 个事件" |
| 每日触发槽位 | 1–2 次；30 天合计约 45–60 次 | 内核档 §5.4 频控预算 |
| weight 域 | 1–100；教学事件走 Director 固定脚本通道，不占权重池 | M1 脚本版 / M2 条件触发版 |
| cooldownDays 域 | 1–14；`maxPerRun` 默认 2 | 防重复疲劳（设计方案 4.3 变奏原则） |
| 效果护栏 | **事件禁用 KILL_TENANT**（死亡只能来自夜战，守住 M0"疼但不死"因果链）；单事件 ADD_PANIC ≤25、ADD_GOLD ≤3,000 | M0 死亡带护栏 + v1.0 applyEffects 单点校验 |
| 恐慌联动 | 事件可 ADD_PANIC / SET_FLAG(panicRelief)，但 D1–D7 教学段受 `TUTORIAL_PANIC_CAP=30` 封顶 | v1.0 §5.3 恐慌数值化 |

## 7. 落地与验收

1. M1：A 组 8 条进固定脚本通道（写死天数触发），其余不入包。
2. M2：B/C/D 组 42 条随 `event_lib.json` 导出进 Director 权重池；schema 校验（p 合计=1、效果白名单、护栏断言）进 CI。
3. M2 验收指标：30 天模拟内权重池条目触发覆盖率 ≥80%（未被触发的条目回调 weight 或 prereq）；单条目平均出场 ≤3 次。
4. 文案基调复核：无"苟神"字样（IP 切割红线，见命名文档 §1.4）✓。
